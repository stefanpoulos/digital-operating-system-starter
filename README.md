# Digital Operating System Starter

A guided way to turn one recurring team workflow into shared knowledge that people and AI can use.

This companion to **Build Your Digital Operating System, One Workflow at a Time** helps a team create its first working piece of a Digital Operating System. It does not require a new platform or a complete knowledge audit. It begins with one real task, asks a few questions at a time, and produces a starter package the team can review.

## What it produces

The guided interview creates:

1. A workflow brief
2. A map of the relevant expertise areas
3. A register of sources, owners, and gaps
4. Draft guidance with supporting evidence
5. Reusable AI workflow instructions
6. A five-case test plan
7. A shared setup based on the tools your organization already uses
8. Human approvals, maintenance responsibilities, and next actions

## What you need

Start with:

- One recurring task with a visible beginning and end
- One recent example of that task
- The original request, finished work, and review feedback if available
- Access to your organization’s approved AI assistant

You do not need to collect every document before you begin. Missing information becomes a visible gap, not an invitation for AI to invent an answer.

## How to use it

1. Open [`guided-starter-prompt.md`](guided-starter-prompt.md).
2. Copy the complete prompt into your organization’s approved AI assistant.
3. Answer the interview a few questions at a time.
4. Supply only sources your organization permits you to use with that assistant.
5. Review the starter package with the people responsible for its sources and decisions.
6. Test the workflow with past examples before connecting it to more systems or giving it more authority.

See [`sample-output.md`](sample-output.md) for a fictional component-review example.

## Where the outputs can live

Use your existing stack. The tool matters less than shared access, clear ownership, current sources, and traceable decisions.

| Purpose | Options |
| --- | --- |
| Shared documentation | Notion, Confluence, SharePoint with Word, Google Docs in a shared drive |
| Source register and test results | Notion database, Microsoft Lists or Excel, Google Sheets, Confluence table |
| Requests and unresolved decisions | Jira, Microsoft Planner, Notion task database, shared spreadsheet for a small pilot |
| AI-assisted work | Your organization’s approved assistant, using supplied documents or tested source connections |
| Design and implementation evidence | Figma, Storybook, and your team’s code repository |

## Human review is part of the workflow

The starter distinguishes source facts, confirmed guidance, draft guidance, and open questions. AI can help collect, organize, draft, apply, and check knowledge. People remain responsible for approving guidance, resolving product tradeoffs, evaluating consequential decisions, and changing authoritative sources.
